# getEventLog短只读能力核对卡

2026-10-26，待单独授权；当前不执行。本卡细化已认可证据窗口设计的生产前置核对，不允许开启窗口或经济试点。

## 范围与前提

最多3个独立样本、总计≤60秒，固定shard3/W49N41，利用既有母房自然行为观察，不派scout、不生成HARVEST/TRANSFER等测试动作，不为获取样本修改任务/库存/工地。失败不重试，不切换或修改共享网络配置。W48N41若无视野明确为未知，不为核对临时开启侦察。

执行前另有新鲜版本/关闭状态核对：默认关闭发布须已确认，保护开关与evidenceWindow均关闭；不能把未来发布授权视为本卡授权。若该前提核对失败，不调用getEventLog。探针工具本地实现和离线边界验证也须在实际执行前完成，目前没有声称工具已实现或生产可用。

## 样本合同

每个样本分别记录：观察Game.time/本地收发时间/运行版本；声明对应的eventTick=Game.time-1；方法存在、返回shape和实际CPU读数；有界原生事件类型/objectId/targetId/resourceType/amount，以及可确认的相关对象id/type/role、原生坐标和energy。只读限定字段，不输出完整Memory、actor Memory、完整房间日志或凭据。

- 每个实际tick母房getEventLog最多一次；最多检查128事件，超量标partial，不把前缀当完整。
- 只处理声明中的HARVEST/TRANSFER字段；BUILD的进度和REPAIR的hits不能当energy费用。错误类型/金额、未知方向、对象已死亡无法识别等保留unknown。
- 使用与记录器相同的初始CPU保护：bucket≥5000、开始剩余≥7，reserve5/maxCapture2为阶段软预算。超预算停止余下可选工作；不声称可以抢占一个原生调用或保证硬CPU终止后留存。
- 请求表达式JSON转义后的长度≤1024；每个样本包含明确标签，收包不得串tag/版本/tick。样本不是连续窗口；只有实际取得相邻tick，才能比较该相邻区间。
- 方法存在、shape合法、生产语义核实三个结论分开。只能用母房自然出现且归属可分辨的事件核对方向/金额/tick；存在并发、源头不可见或只有一个后态，不能倒推动作顺序或金额归因。

## 核对与输出

1. 在本地先用模拟Game验证探针只读、长度/输出/CPU与上限约束，再获得该卡的明确执行授权；不通过不联网执行。
2. 既有只读连接上核对前提，最多3样本且到60秒即停止；不自动重连、追加样本或换节点来补足期望事件。
3. 逐项报告method/shape、HARVEST方向/金额/tick、TRANSFER方向/金额/tick及CPU。缺少自然样本就标missing，不能因抓到一次TRANSFER而同时宣称HARVEST通过，也不能用源码声明或模拟数据填补生产缺口。
4. 原生语义证据保存为本地带样本标签、代码版本及SHA-256的独立档案。不自动向policy写verified=true，不把它直接导入观察窗或改原账；以后需要生产语义引用时另行审阅导入合同。
5. 最后只读确认保护开关仍关闭。连接失败或读回缺失就报告该事实；不发送任何关停/恢复/控制Memory命令。
