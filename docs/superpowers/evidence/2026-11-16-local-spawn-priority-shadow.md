# W49N41 本房补员优先级和预算影子对照

P1.2 以 8399eac 的旧链和 P1.1 人口读契约为基线。[LocalSpawnPlanner](../../../src/governance/LocalSpawnPlanner.js) 读取房间、角色配额、矿点、恢复和 Controller 的事实，使用既有 BodyBuilder 的配体结果，输出本房岗位的需求、优先级、配体上限、成本和无有效 body 原因。按矿工、运输者、升级者、建造者、维修者的顺序决策，已成功配体的意图才可用于后续岗位的配额判断。

[SpawnBureau.replayLocalSpawnDecisions](../../../src/services/SpawnBureauService.js) 从当前 Game、RoomPhase 和配置只读采集一次事实。影子入口不会标准化或保存 Memory，不发布 EventBus 事件。当前仅由离线回放调用。常规 tick 仍走旧 SpawnBureau 仲裁，包含外部需求、现有 upgradeWork 仲裁、排序和原过期语义。具体 Spawn 席位与剩余实有能量继续由 SpawnService 判断。每个意图的候选成本无法证明已经取得席位或扣费。

| 对照场景 | 新旧共同结果 |
| --- | --- |
| 无矿工，149／150 可用能量 | 149 时普通补员优先级 90，按房间容量选体，仍须等 Spawn 端可用能量。150 时优先级 120，使用 150 能量的应急体 |
| 首个运输者，99／100 可用能量 | 99 无有效 body；100 时优先级 90、当前能量上限 100。已有一个运输者时，补足岗位优先级 45、按房间容量 |
| 双矿点与缺 body 的孵化 | 双矿点无覆盖时保持原矿点顺序和当轮恢复优先级。A 点有 body 未知的在孵矿工时只考虑 B 点；不为未知 body 虚构 WORK |
| Controller 5000／4999 | 恢复中 5000 无升级者需求。4999 允许以当前能量规划优先级 60 的升级者，矿工仍为 120 |
| 常态与恢复中的建设维护 | 常态可补普通建造者和维修者。恢复期保留必要工地、紧急维修，预算按当前能量。自定义恢复关闭与 Controller 阈值、维修 backlog 也与旧链一致 |
| 低级房间与同 tick 岗位依赖 | 无仓库且容量 300 的运输空缺优先；首名运输者无法配体时，普通升级和建造需求保持关闭 |

[影子回归](../../../src/tests/local-spawn-shadow.cjs)以同一个模拟房间和同 tick 世界输入分别经过旧 addEconomicIntents 和新计算，比较岗位、顺序、预算、成本、body、quotaKey 和阻塞原因。另执行真实 analyze 入口核对事件及原期限。覆盖的输入没有输出差异。旧实现暂作为离线对照和回退依据，后续只有明确批准的单房接入才可使用新计算结果发布。线上优先级、真实产能和实际支出仍待对应验收。

验证记录：新增入口前，6 项因缺少影子入口按预期失败。实现后 9 项影子回归通过，既有快照通过。npm test 退出 0，smoke、Room Governor 和 1021 项 Node 测试通过。Rollup 未指定 DEST 的离线编译退出 0。
